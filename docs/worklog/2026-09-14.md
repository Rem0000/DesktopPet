# 2026-09-14 工作日志

## 本次变更：会话级链路追踪模块 `add-agent-trace-module`（P0→P3）

对标 DeepSeek Harness 的 `session.jsonl`，把桌宠 Agent 的观测从「一次工具调用写一条日志」升级为**会话级完整链路追踪**：用户消息 → 7 个图节点耗时 → 每次模型调用的 token 用量与首字延迟 → 规划决策与被丢弃原因 → 工具真实入参与真实输出 → 检索命中（复用已有分数）→ 轮次终态；并提供独立的「链路追踪台」窗口。

## 关键设计取舍（决策已记录在变更 design.md）

1. **不做金额换算**：只呈现 token（token 是一手可核对数据，内置单价会过期，展示错误成本比不展示更糟）。
2. **允许读缓存**：`ContextUsageTracker` 可作 IPC 快路径，但写入真值只有链路日志一份，缓存必须可由日志重建。
3. **不做跨会话统计视图**：追踪台只做会话列表 + 单会话轮次时间轴。
4. **不做逐 token 采集**（连开关一起删）：三个复盘问题（慢/贵/错）都不依赖逐 token 时序，代价是十倍体积与一条平时不触发的未验证路径；将来按前向兼容规则新增事件类型即可加回。

## 过程中发现并修复的缺陷

- **修复未截断残行**（由新增的「强杀」用例暴露）：原实现直接向含无换行残行的文件追加收尾事件，追加内容会被并入残行形成不可解析行，导致收尾事件与历史事件一起读不出来。改为先按 `committedBytes` 截断未提交区、再追加收尾；新增用例覆盖「残行被忽略 + 收尾可读 + 摘要显示 `interrupted`」。
- **一次工具使用失误（已回滚重做）**：用 PowerShell 正则批量改写测试 mock 时破坏了 `agentRuntime.test.ts` / `chatService.test.ts` 的 UTF-8 编码，已 `git checkout` 回滚并改用 edit 工具逐处重做。结论：本仓库文件批量改写只用 edit/write 工具。
