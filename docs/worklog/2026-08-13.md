## Skills 技能模块（渐进式加载）落地

为聊天 agent 引入 skills(技能)模块,采用**渐进式加载**:启动只加载轻量技能索引,命中意图才加载技能的核心规则与工具数据,使用结束卸载。OpenSpec change:`2026-08-13-agent-skills`。

### 技能目录格式(标准)
- 每个技能一个独立目录:`skills/<id>/` 内含 `skill.md`(frontmatter 索引 + 核心规则正文)、`script/tools.js`(工具实现)、`references/`(可选参考资料)。
- 技能目录随版本控制,并作为 electron-builder `extraResources` 打包为 `resources/skills/`(同 live2d 先例);`resolveSkillsRoot()`(projectPaths.ts)开发态解析项目根 `skills/`、打包态解析 `process.resourcesPath/skills`,支持 `DESKTOP_PET_SKILLS` 覆盖。

### 三层结构 → 代码映射
- **第一层 索引表(常驻)**:`SkillRegistry.scan()` 扫描 `skills/*/skill.md` frontmatter(id/名称/触发词/优先级/描述),不读正文、不加载 script。
- **第二层 核心规则**:命中时 `loadRules()` 读 `skill.md` 正文,`createSkillRouter` 注入 systemPrompt 专属区块。
- **第三层 工具与数据池**:命中时 `loadScriptTools()` 动态 `require` `script/tools.js`,工具按 `AgentTool` 契约(`execute`)注册进 `ToolRegistry`;技能内模块级内存存状态(猜谜 `game_secret/game_attempts`、共情 `last_emotion`)。

### 触发路由(skillRouter)
- `AgentRuntime` 新增 `skillRouter` 构造参数,在 `recall` 节点组装 systemPrompt 时对最新用户输入做**确定性触发词扫描**。
- 优先级:情绪技能(共情,priority 100)> 游戏(猜谜,50);游戏中表达情绪强制切到共情(体现高情商)。
- **互斥**:同一时刻只激活一个技能,切换时先 `deactivate` 旧技能(注销工具 + 清缓存)。
- **退出**:命中退出关键词(「不玩了/算了/结束」)卸载当前技能回闲聊;游戏中无关提问由规则声明按 /btw 处理,路由不打断。
- 技能工具注册/注销由 `createSkillRouter` 持有 `registeredTools` 清单,切换/卸载时通过新增的 `ToolRegistry.unregister()` 注销。

### read_skill_file 工具

## 有状态多轮技能加固（猜数字可靠性）

真实会话（26200271 / 3e2a8de6）暴露渐进式加载对有状态多轮技能不匹配：模型编造整场胜负、或跳过工具凭记忆编提示。

### 根因
1. **工具结果可观测性缺口**：`formatToolResultsForModel` 把所有成功工具结果折叠成「成功」，`compare_guess` 的 `status/attempts` 不进模型上下文——模型拿不到真值只能编。
2. **给答案消灭调工具动机**：迭代 1 把 `generate_secret` 谜底注入模型上下文 → 模型自认知道答案、跳过 `compare_guess`（会话二实证 75/38 两轮跳过工具）。

### 五条修复
1. **谜底绝不回填**：`generate_secret` 只回填「谜底已生成（仅存在于工具状态中，你不可见；每次用户给数字必须先调用 compare_guess）」——模型不调工具就无从判断大小。
2. **skill.md 硬规则**：每次数字必须先调 `compare_guess` 拿真实判定、模型永远不知道谜底、未调工具禁止回复任何判断。
3. **游戏状态按会话隔离**：`tools.js` 全局模块变量 → `Map<sessionId, game>`（`sourceSessionId` 由 `withSourceSession` 注入），跨会话互不干扰、同会话多轮续局。
4. **工具一次性加载常驻**：chatController 启动即注册猜数字三个工具到 `defaultToolRegistry`，不绑定技能激活态，切换/退出后工具仍在规划集。
5. **猜中后次数重置**：`generate_secret` 幂等仅覆盖 `attempts===0`（未猜过），猜过/残留一律开新局——修复"猜中残留状态 → 下一局次数延续"。

### 验证
- `guessnumberTools.test.ts`（幂等/会话隔离/次数重置/缺会话报错）+ `agentRuntime.test.ts` 结果回填与谜底不泄露用例。
- `npm run typecheck` 通过；全套 `npm test` 49 文件 293 用例通过，无回归。

### 遗留 / 后续
- 需真实 UI 玩一局验证模型每轮都调 `compare_guess`、两会话同时开局互不干扰。

## 会话摘要触发点提前到「可见窗口溢出」（消除丢消息无摘要区）

发现滚动摘要的触发点仍偏晚:`ensureSessionSummary` 只在**完整历史总量 > budget** 时才生成摘要,但可见窗口(`trimToBudget(messages, remaining)`,余量 ≈ 预算 − systemPrompt − 5%)远小于预算先溢出——总量 26k~40k 之间,最早那批消息被窗口静默丢弃、且没有任何摘要兜底,直接从上下文消失。

### 改动(`memoryService.ts`)
- **触发语义** `total > budget` → **可见窗口溢出(存在被窗口丢弃的 early 消息)**。`assemble` 先按不含摘要的 systemPrompt 估算余量、用与 `trimToBudget` 相同的口径反推被丢弃的 `early`,传给 `ensureSessionSummary`;`ensureSessionSummary` 直接消费 `early/recentIds`,不再自己猜窗口边界。
- **窗口边界稳定**:摘要槽始终预留 `0.12·budget`(`SUMMARY_BUDGET_RATIO`),不随「是否已有摘要」漂移——否则摘要首次出现会让窗口收缩、挤出更多未概括消息,造成反复重摘要。
- 增量推进(`coveredUntilMessageId`)+ 4000 字符重生成闸门、失败回退要点列表:原逻辑保留。

### 验证
- 新增回归单测「可见窗口刚溢出即触发摘要(总量仍未超预算)」:55 条 ×100 字 ≈ 5.5k < 6k 预算,但窗口溢出仍生成摘要——锁住新触发语义。
- `npm run typecheck` 通过;`memoryService`/`agentRuntime`/`evals` 相关用例全绿,无回归。

### 遗留 / 后续
- 若想更保守的触发节奏,可把触发点改为 `summaryTriggerRatio`(如 90%·窗口)可配置——本期按「消息刚被挤出就概括」的最早触发落地。
