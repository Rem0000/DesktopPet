# 2026-08-18 工作日志

## 工具输出渲染模型重构（renderForModel 下放，修复 RAG 引用接地）

OpenSpec change：`tool-output-render-model`。

### 事故根因（两次真实事故同源，结构性失效）
`formatToolResultsForModel`（`electron/chat/agentRuntime.ts`）是中央按工具名分派的格式化开关：内容型工具（`search_history`/`web_search`/`web_fetch`/技能）有专属透传分支，其余成功工具一律折叠成通用占位符「成功，可在回复中自然确认已完成，不要复述 JSON」。这导致检索/工具的原文内容不进模型与评测上下文：

1. **猜数字技能（§14，8-13 已修）**：`compare_guess` 的 status/attempts 被折叠出上下文，模型拿不到真值而编造游戏胜负。
2. **本次（P1）**：`search_knowledge` 的 excerpt 被剥掉，RAG 引用失去接地。真实 LLM judge 因看不到检索原文，把 grounded 回答判 1 分；隔离实验（P1 组装层确定性复现 + P3 真模型对照）证明「原文透传即逐字引用」，故障定位在组装层而非检索或模型能力。

根因是结构性的：新增工具必须手动记得补「内容透传」分支，漏了就静默退化，无强制约束、无测试兜底。

### 方案（D1–D6）
- **D1 `renderForModel` 下放**：`AgentTool` 新增 `renderForModel(output, guardConfig?) => string`，每个工具负责渲染自身 `execute` 的成功输出。保持文本 prompt 契约（provider 不变、`formatToolResultsForModel` 调用点不变），改动面最小。替代方案（原生结构化 tool-use）记为后续方向。
- **D2 职责收敛**：`formatToolResultsForModel` 只保留跨工具回复策略（失败/取消/记住意图/关系意图硬约束、空成功提示、不可信区隔离标记），成功结果渲染全部委托 `registry.get(tool).renderForModel(output, guardConfig)`。
- **D3 注册强制校验**：`ToolRegistry.register()` 在 `renderForModel` 缺失时 `throw`（fail-fast），消灭静默退化；判定「结果是否进模型」从「中央 switch 是否有分支」改为「是否注册即保证有渲染」。
- **D4 `search_knowledge` 内容透传（关键修复）**：对齐 `search_history`，命中 excerpt 逐字透传 + `markUntrustedList` 隔离 + 「引用 MUST 逐字取自以下 excerpt，不得补充结果外内容」；空命中如实说明禁止编造。
- **D5 judge 断言加严**：real 模式从「至少一条 pass」改为「与 expectedPass 符合率 ≥ 0.8」+ `citation` 分类 2/2 必过（citation-faithful MUST pass、citation-fabricated MUST fail）；mock 模式保持确定性回归。
- **D6 回归测试防复发**：单测锁定「search_knowledge excerpt 经 `formatToolResultsForModel` 后仍在提示词」（即 P1 探针断言）+「注册缺 renderForModel 抛错」。

### 改动清单
- **契约与注册**：`src/chat/contracts.ts` 给 `AgentTool` 加 `renderForModel`；`electron/chat/toolRegistry.ts` `register()` 强制校验。
- **工具实现（11 个工具全部补 renderForModel）**：
  - 内容型：`search_history`（historySearch）、`web_search`/`web_fetch`（tavilyTools）、`search_knowledge`（knowledgeService，**新写**）、`read_skill_file`（skillFileTool，技能资产内容透传 + 长度上限）。
  - 技能：`skillRegistry.normalizeScriptTool` 注入默认 renderForModel（`formatSkillResultLine` 从 agentRuntime 迁入，含 `compare_guess` 真值 status/attempts 渲染、`generate_secret` 谜底绝不回填、软失败如实行）。
  - 无内容型专属成功行：`update_profile`/`remember_fact`/`forget_memory`（memoryService）、`update_relationship`（relationshipService）、`schedule_reminder`/`cancel_reminder`（reminderService；cancel 的软失败 `ok:false` 如实说明，替代原「成功」谎报）。
- **`formatToolResultsForModel` 重构**：签名加可选 `registry?: ToolRegistry`；成功项委托渲染；删除通用「成功，不要复述 JSON」占位符分支；跨工具策略原样保留；model 节点传入 `tools`。
- **judge eval**：real 断言加严；`buildToolNote` 注入 search_knowledge 注册表，让 citation 场景的 judge 看得到检索原文。
