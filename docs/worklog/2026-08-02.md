## 三、诊断「长对话上下文遗忘」→ 修复（核心）

**根因**（`electron/chat/`）：
1. `normalize` 把全量会话硬裁到 24k 字符，最老轮次被静默丢弃；
2. **会话摘要触发条件实际永不成立**：`ensureSessionSummary` 的 `total > budget` 判断发生在 `normalize` 裁剪之后，收到的消息恒 ≤ 24k → 摘要几乎从不生成；
3. 对话轮次不自动沉淀，模型只靠近期窗口 +（失效的）摘要。

**修复方案**（参考 Claude Code 的分层上下文：Level 0 系统提示 → Level 1 可检索记忆 → Level 2 滚动摘要 → Level 3 近期原文，另加 Level 2.5 包级历史检索）：

| 改动 | 说明 |
|---|---|
| **滚动会话摘要** | `AgentRuntime` 图状态增 `allMessages`（裁剪前完整历史），`recall` 用完整历史调 `assemble` 生成摘要；`coveredUntilMessageId` 增量推进；`provider.summarize` 改 head+tail 采样；失败回退要点列表 |
| **预算可配置** | 默认 24k→40k，`data/config/context-config.json` 可覆盖（非法回退默认） |
| **`search_history` 工具** | 新增 `electron/chat/historySearch.ts`：BM25-only（不依赖 embedding）、作用域当前活跃包全部会话、带出处、`formatToolResultsForModel` 硬约束（逐字引用/空命中禁编造）、规划窄触发、不进二次规划 |
| **上下文占用观测** | `chat:context:usage` IPC + 聊天窗 "上下文 X%" 占用水位（>90% 警示） |
| **RAG 检索开关** | 知识库面板一键开关对话内知识库检索（关闭后 `search_knowledge` 不规划 + 执行被拒），减少无关上下文占用；持久化于 `tool-config.json` |

**OpenSpec**：开启新 change `context-management-strategy`（proposal/design/specs/tasks 4 artifacts 全就绪），规格覆盖 `context-management`、`conversation-history-retrieval`（新增）+ `agent-memory`、`pet-agent-runtime`（修改）。
