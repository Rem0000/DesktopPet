# 常见使用场景

- 异步发送
- mysql和redis，es之间的数据同步
- 分布式事务

# 什么是削峰填谷？

**削峰填谷就是利用消息队列缓冲突发流量，将瞬间高峰请求均匀分配到后续时间段处理，保护下游系统稳定运行**

------

## 典型场景（秒杀 / 优惠券必说）

1. 用户抢券请求 → 写入 MQ
2. 后端消费者**固定速率**消费
3. 无论瞬间多少人抢，DB 始终匀速处理
4. 不会因为流量突刺导致系统雪崩

## 3. 配置类：交换机 + 队列 + 绑定

```java
import org.springframework.amqp.core.*;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class RabbitConfig {

    // 队列名
    public static final String QUEUE = "test.queue";
    // 交换机名
    public static final String EXCHANGE = "test.exchange";
    // routingKey
    public static final String ROUTING_KEY = "test.key";

    // 声明队列
    @Bean
    public Queue testQueue() {
        // durable: 持久化队列
        return new Queue(QUEUE, true);
    }

    // 声明交换机（direct直连模式）
    @Bean
    public DirectExchange testExchange() {
        return new DirectExchange(EXCHANGE, true, false);
    }

    // 绑定：队列 ↔ 交换机 ↔ routingKey
    @Bean
    public Binding binding() {
        return BindingBuilder.bind(testQueue())
                .to(testExchange())
                .with(ROUTING_KEY);
    }
}
```

## 4. 生产者（发送消息）

```java
import org.springframework.amqp.rabbit.core.RabbitTemplate;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Service;

@Service
public class MqProducer {

    @Autowired
    private RabbitTemplate rabbitTemplate;

    public void sendMsg(String msg) {
        // 发送：交换机、routingKey、消息体
        rabbitTemplate.convertAndSend(
                RabbitConfig.EXCHANGE,
                RabbitConfig.ROUTING_KEY,
                msg
        );
    }
}
```

## 5. 消费者（监听队列 + 手动 ACK）

```java
import com.rabbitmq.client.Channel;
import org.springframework.amqp.core.Message;
import org.springframework.amqp.rabbit.annotation.RabbitListener;
import org.springframework.stereotype.Service;
import java.io.IOException;

@Service
public class MqConsumer {

    // 监听队列
    @RabbitListener(queues = RabbitConfig.QUEUE)
    public void consume(String msg, Channel channel, Message message) throws IOException {

        try {
            // 1. 业务处理
            System.out.println("收到消息：" + msg);

            // 2. 手动ACK
            // multiple: 是否批量确认
            channel.basicAck(message.getMessageProperties().getDeliveryTag(), false);

        } catch (Exception e) {
            // 消费失败：拒绝 + 重新入队
            // requeue = true 重新入队，false 进入死信
            channel.basicNack(message.getMessageProperties().getDeliveryTag(), false, true);
        }
    }
}
```

# 如何保证消息不丢失？

## 消息丢失的可能环节

- **生产者发消息时丢了**（网络故障、MQ 挂了）
- **MQ 自己内存丢了**（宕机、队列没持久化）
- **消费者刚拿到就挂了**（没消费完就自动 ACK）

## 1.生产者确认机制

- 生产者发送消息 → MQ 收到后**返回 ack**

- 收到 ack 才算发送成功

- 没收到则重试 / 日志告警

![image-20260422164934717](RabbitMq.assets/image-20260422164934717.png)

## 2.消息持久化

mq默认是内存存储消息，开启持久化功能可以确保缓存在mq中的消息不丢失

### 交换机持久化

```java
@Bean
public DirectExchange simpleExchange(){
    //参数：交换机名称 是否持久化 没有队列绑定时是否自动删除交换机
    return new DirectExchange("name",true,false);
}
```

### 队列持久化

```java
@Bean
public Queue simpleQueue(){
    //使用durable构造持久化队列
    return QueueBuilder.durable("name").build();
}
```

### 消息持久化

```java
Message mag = MessageBuilder
    .withBody(message.getBytes(StandardCharsets.UTF_8)) //消息体
    .setDeliveryMode(MessageDeliveryMode.PERSISENT) //持久化
    .build();
```

SpringAMQP中的消息默认是持久的，可以通过`MessageDeliveryMode`指定

## 超简口诀

- 生产者：**Confirm 确认 + 回退机制**
- 服务端：**交换机、队列、消息 三持久化**
- 消费者：**手动 ACK，不完成不确认**

# 重复消费问题

消费者的确认消息，由于网络波动或者其他原因，导致确认消息没有发送到消息队列

导致消息队列中的消息没有被删除

消费者又重新获取消息后，出现了消息被重复消费的问题

有可能是消费者处理超时/宕机，没来得及发送确认ACK



MQ 本身**无法保证只投递一次**，只能保证**至少投递一次**。

所以必须由<span style="color:#FF0000;">**业务端做幂等性**</span>：**同一条消息无论消费多少次，结果都一样**

## 解决方案

- 全局唯一id
- 幂等性，一般方案无法完全保证不出现重复消费的情况，所以需要客户端面对不同的业务做好幂等性
  - 无论重复多少次，最终结果一致
- <span style="color:#CC0000;">消费记录表+事务（兜底）</span>，消费者消费成功后记录消费记录。消费前，查询一下是否有相同的记录。需要保证插入消费记录和执行业务在一个事务中。

## 全局唯一ID

流程：

1. 生产者发送消息时，带上**唯一 msgId / 业务唯一 ID**，将该id存入redis
2. 消费者拿到消息，先**拿 ID 去 Redis 获取**
3. 获取成功 → 执行业务，并删除redis的ID的key（如果删除前，消费者宕机了，仍然存在重复消费的可能，此时需要业务保证幂等性）
4. 获取失败 → 说明已消费，直接 ACK 丢弃

## 保证幂等性

### 异步插入业务

- 建表时给 **orderId / userId + couponId** 建**唯一索引**

- 重复消息插入时报**唯一键冲突**，捕获后直接 ACK 即可

在插入的表中，设置唯一索引

### 业务更新业务

在mysql层面，更新的时候使用乐观锁



即：

重复消费不可怕，<span style="color:#00994C;">关键要做幂等性</span>；

唯一 ID 加锁最通用，唯一索引最简单。

# mq实现延迟队列

<span style="color:#CC0000;">延迟队列=死信交换机+TTL</span>

## 死信交换机

死信交换机需要队列指定了死信交换机，该队列中的死信才会被送入死信交换机

死信交换机也会又个死信队列

### 什么时候进入死信？

1. 消费者发送消费失败的信号，并**设置不重新入队**
2. 消息过期了
3. 消息队列满了后投递的消息

### 指定死信交换机

```java
@Bean
public Queue ttlQueue(){
    return QueueBuilder.durable("queuename") //队列名称
        .ttl(10000) //10s 延迟
        .deadLetterExchange("dl.direct") //指定死信交换机名称
        .build();
}
```

## 实现示例

### 1.手动实现

```java
//理解原理
@Configuration
public class DelayedQueueConfig {

    // ==================== 死信队列相关 ====================
    public static final String DEAD_LETTER_EXCHANGE = "dlx.exchange";
    public static final String DEAD_LETTER_QUEUE    = "dlx.queue";
    public static final String DEAD_LETTER_ROUTING_KEY = "dlx.key";

    // ==================== 业务TTL队列（过期队列） ====================
    public static final String TTL_QUEUE = "ttl.queue";
    public static final String TTL_EXCHANGE = "ttl.exchange";
    public static final String TTL_ROUTING_KEY = "ttl.key";

    // 1. 死信交换机
    @Bean
    public DirectExchange dlxExchange() {
        return new DirectExchange(DEAD_LETTER_EXCHANGE, true, false);
    }

    // 2. 死信队列（真正消费的队列）
    @Bean
    public Queue dlxQueue() {
        return new Queue(DEAD_LETTER_QUEUE, true);
    }

    // 3. 绑定死信交换机和死信队列
    @Bean
    public Binding dlxBinding() {
        return BindingBuilder.bind(dlxQueue())
                .to(dlxExchange())
                .with(DEAD_LETTER_ROUTING_KEY);
    }

    // 4. TTL业务交换机
    @Bean
    public DirectExchange ttlExchange() {
        return new DirectExchange(TTL_EXCHANGE, true, false);
    }

    // 5. TTL队列：设置死信转发规则
    @Bean
    public Queue ttlQueue() {
        Map<String, Object> args = new HashMap<>();
        // 设置死信交换机
        args.put("x-dead-letter-exchange", DEAD_LETTER_EXCHANGE);
        // 设置死信路由键
        args.put("x-dead-letter-routing-key", DEAD_LETTER_ROUTING_KEY);
        // 设置队列统一过期时间 10秒（可在发送消息时单独指定）
        args.put("x-message-ttl", 10000);
        return new Queue(TTL_QUEUE, true, false, false, args);
    }

    // 6. 绑定TTL队列和TTL交换机
    @Bean
    public Binding ttlBinding() {
        return BindingBuilder.bind(ttlQueue())
                .to(ttlExchange())
                .with(TTL_ROUTING_KEY);
    }
}

//监听死信队列
@Service
public class DlxConsumer {

    // 监听死信队列
    @RabbitListener(queues = DelayedQueueConfig.DEAD_LETTER_QUEUE)
    public void consume(String msg, Channel channel, Message message) throws IOException {
        try {
            System.out.println("延迟消息消费成功：" + msg + "，时间：" + System.currentTimeMillis());
            channel.basicAck(message.getMessageProperties().getDeliveryTag(), false);
        } catch (Exception e) {
            channel.basicNack(message.getMessageProperties().getDeliveryTag(), false, true);
        }
    }
}
```

# 消息堆积问题

- 提高消费者数量
- 提升消费者的消息处理速度
- 扩大队列容量，<span style="color:#FF3333;">惰性队列</span>

## 惰性队列

特点：

- 接收到消息后直接存入磁盘而不是内存
- 消费者要要消费消息的时候，从磁盘中加载到内存
- 支持数百万条的消息存储

## 配置方式

```java
@Bean
public Queue lazyQueue(){
    return QueueBuilder
        .durbale("")
        .lazy()
        .build();
}

@RabbitListener(
	queuesToDeclare = Queue(
    	name = "",
        durable = 'true',
        arguments = @Argument(
        	name = 'x-queue-mode',
            value = "lazy"
        )
     )
)
public void listenLazyQueue(String msg){
    sout("收到消息"+ msg)
}
```
