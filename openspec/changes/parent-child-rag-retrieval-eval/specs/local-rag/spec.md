## MODIFIED Requirements

### Requirement: 切块与索引
系统 SHALL 将导入文档切分为带稳定 `documentId`、父块 ID、子块 ID、正文、偏移与 `headingPath` 信息的父子块结构。父块 MUST 保存可供 Agent 注入的连贯上下文；子块 MUST 按更细粒度建立稀疏（BM25 或等价倒排）与向量双索引。父块与子块 MUST 保留明确的一对多关联，且父块正文不得因每个子块重复持久化。切块 MUST 优先按 Markdown 标题与段落边界分割；仅当父块或子块超过各自配置最大长度时才二次切分并保留 overlap。删除文档时 MUST 同步移除其全部父块、子块、稀疏索引项与向量记录。

#### Scenario: 标题边界生成父子块
- **WHEN** 导入含 `##` 小节标题且正文跨越多个段落的 Markdown
- **THEN** 系统生成具备对应 `headingPath` 的父块，并为每个父块生成一个或多个带 `parentChunkId` 的子块；切分不得在标题行中间切断

#### Scenario: 超长父块二次切分
- **WHEN** 单个标题小节超过父块最大长度
- **THEN** 系统按段落优先、必要时按字符切分为多个父块，并为每个父块独立生成子块；字符切分部分保留配置的 overlap 和可追溯偏移

#### Scenario: 删除文档清理父子索引
- **WHEN** 用户删除某已导入文档
- **THEN** 该文档源文件、全部父块与子块及其稀疏/向量索引不再参与检索，且不得留下指向已删除父块的子块记录

### Requirement: 检索增强回答
系统 SHALL 通过子块命中的 Hybrid 检索（稀疏 + 向量 + 轻量 Rerank）获取候选，并将候选映射为按父块去重的 top-k 上下文提供给 Agent；同一父块最多返回一次。无命中时 MUST 明确可观测的空结果，MUST NOT 捏造文档内容。检索 MUST 使用 `data/knowledge/` 下的父子索引与 `data/models/` 下的 Embedding 权重。

#### Scenario: 子块命中召回父块
- **WHEN** 用户问题与某父块中的一个子块语义相关且 Hybrid 检索命中
- **THEN** 返回该父块的上下文正文，并同时附带 `documentId`、父块 ID、命中的子块 ID、`headingPath` 与分数溯源元数据

#### Scenario: 同父块多子块去重
- **WHEN** 同一父块的多个子块进入稀疏或向量候选集
- **THEN** 最终 top-k 中该父块只出现一次，并使用其最佳子块命中作为排序与精确证据代表

#### Scenario: 未命中
- **WHEN** 知识库为空或查询无关
- **THEN** 检索返回空列表，回复不声称引用了不存在的本地文档

### Requirement: 向量索引生命周期
系统 SHALL 在文档导入、更新或删除时同步维护父子块对应的向量索引；启动时 MUST 校验父子索引 schema/index 版本，发现旧版本或关联不完整时拒绝混用并提供从源文件重建索引的能力（IPC 或开发者命令）。索引写入 MUST 使用向量存储的批量落盘路径，避免逐条全量写文件造成主进程长时间阻塞。重建索引时 SHALL 向调用方报告进度（已完成/总数）。

#### Scenario: 旧索引触发重建
- **WHEN** 启动或检索前发现仅含单层 chunk 的旧索引或父子关联校验失败
- **THEN** 系统将索引标记为待重建，不返回混用结果，并能基于保存的源文件生成完整父子索引

#### Scenario: 导入后立即可向量检索
- **WHEN** 用户成功导入新文档且 Embedding 模型可用
- **THEN** 新父块和子块生成完成，子块向量批量写入索引并参与后续 Hybrid 检索

#### Scenario: 重建进度可观测
- **WHEN** 用户触发知识库索引重建且文档量大于一批
- **THEN** 调用方能收到至少一次中间进度更新（done/total），最终父子块和两类索引一致

### Requirement: 知识库与用户记忆隔离
知识库文档、父子块索引与用户长期记忆（profile/fact 等）MUST 分库存储与分别管理；清空记忆 MUST NOT 删除知识库父子索引，删除知识库 MUST NOT 清空用户记忆。

#### Scenario: 清空记忆保留知识库
- **WHEN** 用户清空全部长期记忆
- **THEN** 已导入知识库文档、父块、子块与索引仍然可用
