## Why

当前知识库以同一粒度的 chunk 同时承担检索命中和 Agent 上下文注入职责：较大的块会稀释检索信号，较小的块则容易缺失回答所需的上下文。需要将知识库升级为父子分块，使子块负责高精度命中、父块负责完整上下文召回，并以未参与实现调参的独立测试集重新评估检索质量。

## What Changes

- 将知识库文档索引从单层 chunk 升级为具有稳定父子关联的两层结构：父块保留完整、可注入的上下文范围，子块按更细粒度建立 BM25 与向量索引。
- 将 Hybrid 检索的候选、排序与溯源链路改为以子块匹配为依据，并在返回结果前聚合/映射至对应父块；同一父块的多个子块不得造成重复的上下文注入。
- 保留并扩展检索结果元数据，使调用方能够追溯命中的子块及被召回的父块、文档、标题路径和偏移范围。
- 更新导入、删除、重建索引与版本迁移行为，确保父块、子块、稀疏索引和向量记录始终一致。
- 新增与现有 source-evidence 语料及调参集隔离的、冻结且可校验的检索测试集，并使用真实 BGE 向量路径输出 Recall@K 与 MRR@K。
- 为新的独立评测提供专用 npm 命令、机器可读报告与最低有效性断言；报告清楚标明语料版本、测试集版本、切分/索引配置和指标口径。

## Capabilities

### New Capabilities
- `independent-retrieval-evaluation`: 冻结的独立知识库检索测试集、真实向量评测入口、可追溯报告及 Recall/MRR 指标定义。

### Modified Capabilities
- `local-rag`: 将知识库文档切分、索引生命周期及检索增强的单层 chunk 行为改为父块召回、子块命中的行为。
- `hybrid-retrieval`: 将统一 Hybrid 检索的知识库候选标识、去重、排序结果与溯源契约扩展为父子块关联模型。

## Impact

受影响范围包括 `electron/retrieval/markdownChunker.ts`、知识库持久化与索引服务、Hybrid 搜索结果类型及 Agent 的知识库上下文格式化路径；现有知识库索引需要通过版本升级或重建转换。评测侧将新增独立 corpus/dataset、评测辅助代码与 npm 脚本，并继续使用本地 BGE-Small-ZH-v1.5 和当前 Hybrid 检索内核，不引入云端依赖。
