# agent-trace-log Specification

## Purpose

会话级链路追踪：把 Agent 主链路的可观测性从「工具调用一条日志」升级为**完整链路事件流**——append-only 结构化日志的格式与写入强度、脱敏与外置原文、读取/分页/实时推送、token 与上下文占用的读侧投影、崩溃与取消终态、保留与导出，以及独立的「链路追踪台」界面。对标 DeepSeek Harness 的 `session.jsonl`（首行 header + 稠密 seq + 崩溃可修复 + 投影而非写回）。

## Requirements
### Requirement: 会话级链路事件日志

系统 SHALL 为每个聊天会话维护一份 append-only 的结构化事件日志，落盘于 `data/traces/sessions/<sessionId>.jsonl`。日志首行 MUST 为不可变的会话头（sessionId、packageId、createdAt、provider 非敏感配置、上下文预算、工具启用快照、脱敏等级），其后每行 MUST 为一个事件。事件类型 MUST 至少覆盖：轮次边界（turn/start、turn/end）、用户与助手消息、图节点执行（step/start、step/end）、模型请求信封与上下文组装（request/header、request/context）、模型调用与结果（model/call、model/result）、规划结果（plan/result）、工具调用与结果（tool/call、tool/result）、工具确认（tool/confirm）、检索命中（retrieval/hits）、技能路由（skill/route）与错误（error）。

列会话 MUST 只需读取首行会话头，MUST NOT 依赖解析完整日志。日志 MUST NOT 记录逐 token 流式增量，MUST NOT 提供此类采集开关；流式过程由模型调用事件的首字延迟、耗时与用量表达。

#### Scenario: 一次完整对话产生可回放链路
- **WHEN** 用户发送一条消息并触发检索工具与最终回复
- **THEN** 该会话日志中存在用户消息、节点执行、模型调用、工具调用与结果、助手消息与轮次结束事件，且可仅凭日志重建该轮完整时间线

#### Scenario: 仅读首行列会话
- **WHEN** 追踪台列出全部会话
- **THEN** 系统通过读取每个日志文件的首行完成列表渲染，不解析全部事件行

#### Scenario: 会话删除清理链路
- **WHEN** 用户删除一个会话
- **THEN** 该会话的链路日志文件被一并删除

#### Scenario: 不落逐 token 增量
- **WHEN** 一次流式回复产生数百个 token 增量
- **THEN** 该轮链路中只有消息级与模型调用级事件，不出现逐 token 的增量事件行

### Requirement: 事件信封与格式版本

每个事件 MUST 携带 `type`、会话内稠密递增且无空洞的 `seq`、epoch 毫秒 `time` 与 `data` 载荷；轮次相关事件 MUST 携带 `turn`。日志 MUST 持久化格式版本号；读取遇到无法识别的版本时 MUST 明确提示需要升级，MUST NOT 报告为文件损坏。读取遇到未知事件类型时 MUST 在事件带前向兼容标记时跳过该事件并继续，MUST NOT 因单个未知事件中断整份日志的读取。

#### Scenario: seq 稠密无空洞
- **WHEN** 一次对话中多个工具并发产生事件
- **THEN** 日志中事件的 seq 从 0 起连续递增，不存在重复或空洞

#### Scenario: 未知事件类型可跳过
- **WHEN** 日志中存在带前向兼容标记的未知事件类型
- **THEN** 读取方跳过该事件并正常返回其余事件

#### Scenario: 未知格式版本
- **WHEN** 日志头的格式版本高于当前支持的版本
- **THEN** 系统提示需要升级应用，且不将该日志判定为损坏

### Requirement: 脱敏与大载荷外置

链路日志 MUST 对疑似 API Key、密码、令牌等敏感片段执行遮罩，MUST NOT 落盘明文凭据；API Key MUST NOT 以任何形式进入链路日志。超过配置上限的字段（工具原始入参、工具输出、系统提示词、模型文本）MUST NOT 直接内联：系统 SHALL 落盘预览、字节长度与内容摘要，并将原文写入 `data/traces/blobs/` 下的内容寻址存储，事件中以定位引用指向该原文。

#### Scenario: 参数含密钥
- **WHEN** 工具入参中包含疑似密钥字符串
- **THEN** 链路日志与追踪台展示的对应片段为遮罩文本，日志中不存在明文密钥

#### Scenario: 超大工具输出外置
- **WHEN** 某工具返回内容超过单字段上限
- **THEN** 事件中记录预览、字节长度、摘要与外部定位引用，原文写入 blobs 目录且可从追踪台按需展开

#### Scenario: 外置原文缺失
- **WHEN** 事件引用的外置原文文件不存在
- **THEN** 追踪台仍展示预览与摘要，并明确标注原文不可用，不阻断其余链路渲染

### Requirement: 写入强度与不侵入聊天

事件写入 MUST NOT 阻塞或破坏聊天主链路：事件提交接口 MUST 为同步调用、MUST NOT 抛出异常、MUST NOT 等待磁盘 I/O；磁盘写入 SHALL 由批处理队列异步完成。落盘失败 MUST 只记录诊断信息与丢弃计数，MUST NOT 影响回复生成、工具执行或流式输出。系统 SHALL 支持 fsync 档位配置，默认在语义检查点（模型请求发出前、工具派发前、每个节点结束）与轮次结束时刷盘。

#### Scenario: 落盘失败不影响聊天
- **WHEN** 链路日志目录不可写
- **THEN** 用户仍正常收到流式回复与工具结果，系统仅记录诊断信息

#### Scenario: 检查点刷盘
- **WHEN** 一次模型请求即将发出
- **THEN** 此前产生的链路事件已刷入磁盘，进程异常退出后仍可读取

### Requirement: 崩溃与取消的终态

被用户取消的轮次 MUST 以 `turn/end` 的取消终态收尾。应用启动时若发现某会话日志停在一轮中间（缺少轮次结束事件），系统 MUST 追加合成的收尾事件（未完成工具的未知结果、节点结束、轮次中断终态），MUST NOT 截断或删除已完成的轮次。

#### Scenario: 用户取消生成
- **WHEN** 用户在流式回复过程中点击停止
- **THEN** 该轮以取消终态结束，追踪台显示为已取消而非失败

#### Scenario: 进程被强杀后恢复
- **WHEN** 应用在轮次执行中途被强制结束并随后重启
- **THEN** 系统为该会话补写中断终态，追踪台将该轮显示为已中断，此前的完整轮次保持不变

### Requirement: 读取、过滤与实时推送

系统 SHALL 提供按会话读取链路事件的接口，支持分页与按轮次/事件类型过滤。读取结果 MUST NOT 因单条损坏行而整体失败。系统 SHALL 提供实时推送通道，使追踪台在对话进行中增量追加事件。

#### Scenario: 分页读取长会话
- **WHEN** 追踪台请求一个包含数百轮对话的会话
- **THEN** 系统按请求的页码与数量返回事件，并给出总数或是否还有更多

#### Scenario: 实时追加
- **WHEN** 新的一轮对话开始执行
- **THEN** 已打开的追踪台无需刷新即可看到新增事件

#### Scenario: 尾部损坏行
- **WHEN** 日志最后一行因写入中断而不完整
- **THEN** 读取忽略该行并返回此前的完整事件

### Requirement: token 用量投影

系统 SHALL 从链路日志折叠出 token 用量：每次模型调用 MUST 记录未缓存输入、输出、缓存读与缓存写四类互斥计数，并单独记录推理 token（作为输出的子集，MUST NOT 重复累加）。未能从 provider 获得用量时，系统 MUST 标记该用量为估算值，MUST NOT 将其当作真实计量。系统 SHALL 提供按轮次与会话聚合的用量投影。系统 SHALL 仅呈现 token 用量，MUST NOT 提供金额换算或成本展示。

#### Scenario: 流式回复被计量
- **WHEN** 一次流式回复完成
- **THEN** 该轮记录中存在输入、输出、缓存读与推理 token 用量，且轮次结束事件携带该轮聚合用量

#### Scenario: provider 未返回用量
- **WHEN** provider 响应中缺少用量信息
- **THEN** 系统以估算方式给出用量并明确标记为估算

#### Scenario: 会话累计用量
- **WHEN** 追踪台请求某会话的用量汇总
- **THEN** 系统返回该会话全部轮次的累计四类计数，缓存读与未缓存输入分别累加、互不混入

### Requirement: 上下文占用与压力投影

每次模型请求前组装的上下文 MUST 作为事件落盘，包含预算与按来源拆分（系统提示词、工具目录、技能规则、记忆召回、消息窗口）。系统 SHALL 从链路日志折叠出上下文占用投影，取代仅保留最近一次的内存快照，供聊天窗与追踪台查询。

#### Scenario: 每次请求记录占用
- **WHEN** 用户连续发送多条消息
- **THEN** 每轮各自的上下文占用均可在链路中查到，而非只有最后一次

#### Scenario: 占用超阈值警示
- **WHEN** 某轮组装占用超过预算的 90%
- **THEN** 查询占用投影时返回警示信号，聊天窗据此提示接近上限

### Requirement: 保留、清理与导出

系统 SHALL 支持链路日志的保留策略配置（保留天数、最大会话数、单文件大小上限），并 SHALL 提供手动清理入口。清理 MUST NOT 删除仍在保留期内的会话日志。系统 SHALL 支持将链路导出为结构化文件与可读报告，导出副本 MUST 再次执行敏感信息遮罩。

#### Scenario: 超期清理
- **WHEN** 存在早于保留天数的链路日志且触发清理
- **THEN** 对应日志与其外置原文被删除，保留期内的日志不受影响

#### Scenario: 导出带遮罩
- **WHEN** 用户导出某会话链路
- **THEN** 导出内容包含事件与用量汇总，且敏感片段已被遮罩

### Requirement: 链路追踪台界面

系统 SHALL 提供「链路追踪台」窗口：左侧列出会话（至少含轮数、累计 token、耗时与工具成功率），右侧按轮次展示时间轴，时间轴 MUST 至少包含用户消息、各图节点的耗时、模型调用卡（输入/输出/缓存/推理 token、首字延迟、结束原因）、工具卡（工具名、真实入参、真实输出或外置引用、耗时、成败、引用来源）与本轮汇总（总 token、总耗时、状态）。工具卡与模型卡 MUST 可展开查看细节，并 SHALL 提供查看原始日志的入口。

#### Scenario: 查看一轮完整链路
- **WHEN** 用户在追踪台选择一个已完成轮次
- **THEN** 界面按时间顺序展示该轮的节点耗时、模型调用、工具调用参数与结果及本轮 token 与耗时汇总

#### Scenario: 查看失败轮次
- **WHEN** 某轮因 provider 错误或用户取消而结束
- **THEN** 时间轴显示该轮终态与错误类别，且保留已发生的事件
