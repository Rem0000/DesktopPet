## Purpose

Agent 离线评测与安全兜底：场景化回归、危险工具确认与敏感信息遮罩。
## Requirements
### Requirement: 离线评测集
系统 SHALL 提供可本地运行的评测场景集：功能回归不少于 20 条（覆盖工具调用、记忆一致性、RAG 命中等），并额外提供检索 IR 标注集。每次运行 MUST 输出可读的通过/失败或指标汇总。

#### Scenario: 运行评测脚本
- **WHEN** 开发者执行功能回归评测命令
- **THEN** 系统输出场景总数、通过数与失败场景标识

#### Scenario: IR 与功能评测分离
- **WHEN** 开发者仅执行 IR 评测
- **THEN** 系统运行检索标注集并输出 P@K/R@K/MRR，不替代功能回归 pass/fail 语义

### Requirement: 检索 IR 离线评测
系统 SHALL 提供带人工标注的检索评测集（覆盖知识库 chunk 与/或记忆条目），本地脚本 MUST 输出 P@K、R@K 与 MRR（K 值在 eval 配置中固定，默认 K=4 或 K=10）。评测 MUST 针对当前实现的单一 Hybrid 管线报告指标，MUST NOT 要求或多方案 A/B 对比实验。默认快速路径可使用 mock Embedding；系统 MUST 提供启用真实 BGE Embedding 的开关，并在文档中区分两种指标含义。

#### Scenario: 运行 IR 评测
- **WHEN** 开发者执行检索 IR 评测命令
- **THEN** 系统输出各 query 的 P@K、R@K、MRR 及汇总均值

#### Scenario: 无对比分支
- **WHEN** 执行 IR 评测
- **THEN** 输出仅包含当前 Hybrid 实现指标，不包含 baseline 对照组或多 pipeline 并排表格

#### Scenario: 真实 Embedding 评测
- **WHEN** 开发者启用真实 Embedding 开关且本地 BGE 权重可用
- **THEN** IR 评测使用真实向量管线输出指标，且输出中可区分该模式

### Requirement: 危险工具确认
风险等级为 confirm 的工具在执行前 MUST 取得用户确认（聊天窗确认 UI 或等价 IPC）；未提供确认回调、用户拒绝、或确认超时 MUST NOT 执行该工具。safe 等级工具可按现有白名单直接执行。

#### Scenario: 确认后执行
- **WHEN** Agent 规划调用 riskLevel=confirm 的工具且用户确认
- **THEN** 系统执行该工具并记录观测事件

#### Scenario: 拒绝则不执行
- **WHEN** 用户拒绝确认
- **THEN** 系统不执行该工具并向对话返回已取消语义

#### Scenario: 超时或无确认通道
- **WHEN** 确认请求超时或聊天窗无法响应确认
- **THEN** 系统 MUST NOT 执行该工具，并记录 ok=false 的观测事件

### Requirement: Confirm 工具功能回归
离线功能评测集 SHALL 覆盖 confirm 级工具「确认后执行」与「拒绝不执行」两类场景，而不仅断言 riskLevel 元数据。

#### Scenario: 评测拒绝路径
- **WHEN** 运行包含 forget_memory（或等价 confirm 工具）且模拟用户拒绝的评测场景
- **THEN** 场景断言工具未执行副作用且观测记录失败/取消语义

### Requirement: 敏感信息遮罩

系统在工具观测日志、会话链路日志、时间线详情、链路追踪台界面与评测输出中 MUST 对疑似 API Key、密码、令牌等敏感片段进行遮罩；遮罩失败时 MUST 宁可截断也不完整落盘明文密钥。遮罩范围 MUST 覆盖链路日志的全部字段（含工具入参、工具输出、系统提示词、模型文本与错误信息）以及外置原文文件；链路导出副本 MUST 再次执行遮罩。

#### Scenario: 日志遮罩密钥
- **WHEN** 工具入参或错误信息包含疑似密钥模式
- **THEN** 持久化日志与 UI 详情中对应片段被替换为遮罩文本

#### Scenario: 外置原文同样遮罩
- **WHEN** 工具输出因超过单字段上限被外置存储，且内容包含疑似密钥
- **THEN** 外置原文中的敏感片段同样被遮罩，追踪台展开时不可见明文

#### Scenario: 导出副本再遮罩
- **WHEN** 用户导出某会话链路
- **THEN** 导出文件中的敏感片段已遮罩，且不影响原始日志

### Requirement: 轨迹忠实性评测

离线评测 SHALL 覆盖链路追踪的忠实性，至少断言：每次模型调用都有 token 用量记录或带估算标记；工具事件记录的入参与输出与该次真实执行一致（不得为占位符或空值）；被取消或失败的轮次具有明确终态；链路写入失败时对话仍正常完成；含疑似密钥的入参不以明文落盘。

#### Scenario: 用量必有记录
- **WHEN** 评测场景执行一次包含工具调用的对话
- **THEN** 断言该轮每次模型调用均有用量记录或估算标记，且轮次汇总用量等于各次调用之和

#### Scenario: 参数与结果忠实
- **WHEN** 评测场景执行带结构化入参的工具调用
- **THEN** 断言链路事件中的入参与输出与真实执行一致，且非空占位

#### Scenario: 终态明确
- **WHEN** 评测场景模拟用户取消或 provider 报错
- **THEN** 断言该轮具有取消或失败的终态事件，且此前事件保留

#### Scenario: 落盘失败不影响完成
- **WHEN** 评测场景令链路日志目录不可写
- **THEN** 断言对话仍返回完整回复，且未抛出异常

#### Scenario: 密钥不落明文
- **WHEN** 评测场景传入含疑似密钥的工具入参
- **THEN** 断言链路日志、外置原文与导出内容中均不存在该明文
